TransLit：让 AI 翻译的书，更像一本书

2026-11-20

完成了 AI 翻译工作流，读到成品才发现版式的毛病一样让人难受。

标题混进了正文，注释一个都点不开。哪怕翻译效果还不错，却总觉得自己在读盗版书（虽然不可谓不是）。

于是重写了 TransLit，就是想让 AI 翻译的电子书，至少看起来像一本“书”。

从能翻译到像本书

TransLit 是个打开浏览器网页就能用的电子书翻译工具。一切流程全都在你自己的浏览器完成，填你自己的模型 API 密钥就行。原书文件和 API 密钥都只保存在当前浏览器本地，不会传输到任何第三方服务器。

这也意味着有一点得提前留意，所有数据都存在本地浏览器里，中途要是换了浏览器或者清掉缓存，还没导出的工作进度就会丢失，所以翻完记得顺手下载保存。

这次重写，我是想保留原书的结构，但是按照中文书的排版习惯重排，导出能直接放进阅读器看的成品。界面也顺手全改成中文，换了个黑白极简风的新 Logo，你能看到“TransLit”的首字母 T 和书页折角，看着比以前要利落不少。

先看一眼主界面吧：

放弃 Markdown 中转，直接改 HTML

据说，Markdown 是 AI 的母语。

之前版本的做法是，先把 EPUB 的每一页转换成 Markdown 格式，丢给模型翻译，整合后再转回 EPUB。

流程很容易跑通，但电子书的部分样式，转化为 Markdown 之后就丢光了。因为原书的 EPUB 很可能只是在 CSS 文件里标注了样式信息，并没有用专门的标题标签。最常碰到的情况就是章节标题或者特殊引文丢了样式标记，导入阅读器后这些内容全部退化成普通正文。

所以，新版弃用了那套 Markdown 中转流程。EPUB 里面本来就是打包好的 HTML 文件，程序会先识别一遍原书的版式语义，把哪块是标题、哪块居中、哪块是引文都标记出来，同时保留原书的骨架。模型翻完文本块之后，程序再把译文按位置填回原来的节点，最后用预设好的中文排版样式接管全书。

这样原书的层次和结构可以保留，版面又能按中文阅读习惯重新排得整整齐齐。

引入“赫蹏”排版规范，所见即所得

为了让译文看着顺眼，新版参考了中文排版规范—— Heti（赫蹏）。

很多改动都落在阅读时的细节上。

比如，外文书里常拿斜体来表示书名或者强调，中文如果硬要用斜体，笔画很容易发虚、起锯齿，所以斜体样式统一转换成了楷体正排。独立成段的引文块也用楷体正排，配上一层浅色底纹和左侧细线。

除了排版，界面布局也清爽了许多。

右侧一大块区域本来全是控制台，现在留给实时排版预览，顶部可以实时切换译文、双语、原文三种视图，所见即所得。

现在右侧底部为状态栏，可以展示章节数、术语数、Token 消耗量和缓存命中率等参数，想看详细日志时，点开右下角的按钮即可弹出控制台。

当前有 6 种版本 EPUB 可以导出。纯译文版、原文在前的双语对照版、译文在前的双语对照版，这三种版式各自又分微信读书专版和通用电子版。选择困难的话，也可以直接点击“导出电子书”按钮，打包成合集 ZIP 带走。

双语留了两种顺序，主要是应付不同的阅读场景。

原文在前适合研读原文，卡住了再往下瞄一眼中文。译文在前更适合顺着中文往下读，碰到拿不准的词句再对照原文，毕竟 AI 翻译不是万无一失的。

不过我只是想读完一本书，还是更喜欢纯译文版，最为沉浸。毕竟双语版篇幅长上一倍，哪怕不读原文，点屏幕也更费劲。但顺手留下双语版也是好的，万一哪天想学外语就能直接派上用场。

脚注，从能用到好用

翻译非虚构或者学术书，脚注最容易出岔子。很多书习惯把注释统一放在独立页面，以前做格式转换时经常断链，几乎不可用。

本着“宁愿不想用也不能不可用”的心态，我添加了双语对照版，也更新了脚注处理方式。

新版在解包时会先扫描全书的引用关系，把独立文件里的注脚搬回对应的章节，同时把原注脚文件锁定，免得重复翻译。在 AI 翻译之前，先用占位符保护正文中的角标，防止模型顺手删改。

导出时，程序会生成弹注气泡，就像前面预览图里展示的那样。

导入手机上的微信读书之后，点一下注脚图标，也会原地弹出气泡。如果是双语版，中文角标弹中文译注，英文角标弹英文原注，两边互不干扰。

打开网页就能用！

作为一款网页应用，TransLit 免去了本地配环境的麻烦，点击链接就能体验（见文末分享卡片）。

配置自己的 API 接口

先在左侧打开 API 接口配置，填好兼容 OpenAI 接口的地址、密钥和模型。

这里支持保存多套 API 配置，随时可以新建、复制或者切换。万一翻到一半碰到某个接口限流，或者某个分片翻译不成功，切到备用模型就能分片重试，不用从头再来。

面板里还做了一键拉取可用模型列表的功能，填完地址和密钥点一下就能选模型，省得再去翻文档复制粘贴一长串模型名字。早就该这样做了。

拖入 EPUB 等待自动预处理

把 EPUB 拖进页面后，程序会自动做完准备工作。

原文语种自动识别、全书脚注提取，还有页面分类都会一并完成。比如自动跳过版权页、纯图封面保持原文、锁定注释源文件。切到右侧的章节目录就能看到每一页的分类结果。

如果发现哪一章的页面分类不合心意，尽管手动修改，是正常翻译、保持原文还是直接丢弃，全由你决定。

选好翻译策略并联动术语库

左侧提供了两种翻译策略，不过在我看来，大多数情况都更适合选择“轻量翻译”，“两步翻译”更像是给之前大模型打的补丁（详见 TransLit：AI 翻译，多人一步）。

下面还可以填写“背景设定与补充说明”，把这本书的背景设定或语言风格交代给模型。不得不说，我几乎没有用过，一般情况下原文的约束就足够了。

翻译过程中，大模型会一边翻译文段，一边抽取书里的“术语”，来确保前后一致性，实时显示到右侧的全书术语库表格里（详见TransLit：AI 翻译电子书之我见）。要是看到哪个词翻得不够妥帖，你直接在表格里手动修改，再点一下“联动已译章节”，新译名就会批量同步回前面已经翻完的章节里，不用自己逐章替换。

问题出现我再告诉大家

说到底，TransLit 就是为了满足我的一己私欲做出来的翻译工具，与其说是开源，不如说是找了个可靠的网盘（GitHub）存着。

每本电子书的底层写法千差万别，我不敢保证当前版本的 TransLit 是通用的，后面要是遇到什么新问题，我还会持续更新打磨。实话实说，之前做过的很多工具都做不到持续使用、持续迭代，幸好我读书的习惯没有完全丧失。

如果你平时也常读外文 EPUB 电子书，却苦于繁琐的翻译流程或者糟糕的翻译效果，欢迎打开试试看，遇到问题随时来仓库提 Issue。

我会鼓励你自己解决，让我们一同踏上“程序自由之路”。
